# 简报 LOOP-001：3D 月相演示网页（讲清"月亮为什么会变形状"）

## 任务
用户原话：「做一个3D模型，在网页里头展示出来，为什么月亮在空中会有不同的形状，是月牙啊，是吧，满月呀，或者半满呢？讲清楚这个。做的精美一点。可以可以调日期是吧？因为月亮不同的日期，它的状态不一样。」

我的理解：做一个**单页 Web 应用**。页面核心是一个**真正 3D 的月亮**（球体 + 真实月面纹理 + 真实光照，不是平面图、也不是 CSS 画的圆），随日期呈现**真实那一天**的月相（盈亏形态、被照亮比例、月相名、月龄、月出月落）。同时页面要有一块**讲得清楚原理**的说明区：让一个从没想过这件事的人读完就明白——**月亮不是自己在变形，是我们在改变看到"被太阳照亮的那个半球"的多少**。用户能**改日期**（选具体某天 + 连续播放时间流逝），整页状态随日期实时更新。

## 验收（可判定，逐条能跑）
1. `npm run build` 退出码 0，产物为纯静态文件；用任意静态服务器打开后**运行时外部网络请求数 = 0**（所有资源本地/打包）。

5. 说明区能回答：为什么会有月牙/半月/满月；为什么**上下弦月的明暗界线是一条直线**；为什么**每次看到的都是同一面**。

## 天文事实基线（策展阶段已核实，可直接写进页面文案）
1. 月球被太阳照亮的**永远只有一半**（除日/月食期间）。地面看到的"形状"= 被照亮半球中朝向我们的那部分的**投影比例**。所以"月亮变形状"其实是"我们看到多少"。
2. **朔望月 = 29.5306 天**（29 天 12 小时 44 分 3 秒）是一个完整月相循环的周期。
3. **月相角 i**（太阳—月球—地球夹角）与**照明比例 k** 的关系：**k = (1 + cos i) / 2**。i=0 → 满月 k=1；i=90° → 上下弦 k=0.5；i=180° → 新月 k=0。
4. **明暗界线（terminator）**是月面上的一个大圆，它在天空的投影是"半长轴 = 月球半径、半短轴 = 半径·sin i"的**椭圆**。所以：满月/新月时它与月面边缘重合（看起来是整圆）；**上下弦时半短轴 = 0，它恰好是一条穿过月面的直线**；其余相位是椭圆弧。这就是"为什么上下弦月中间是一条直线"的答案。
5. **为什么每次都是同一面**：月球自转周期 = **恒星月 27.3217 天** = 公转周期 → **潮汐锁定**，永远只能看到同一面（近地面）。月相变化与"转到哪一面"无关。
6. 月球相对太阳移动 ≈ **12.19°/天**、相对恒星 ≈ 13.18°/天；因此**每天月出比前一天晚约 48–50 分钟**。
7. 月球轨道相对黄道面**倾斜 5.145°** → 朔望时太阳—地球—月球夹角是 180° ± 5.145°，所以"正上弦"那一刻的照明比例**一般不是正好 50%**。
8. **视直径**：月面 0.49°–0.56°（均值约 0.52°，≈30 角分）；太阳 0.52°–0.54°——两者几乎一样大，这是日全食/日环食的前提。地月平均距离 384,400 km，近地点约 356,500 km、远地点约 406,700 km（相差约 14%）；月光到地球约 **1.28 秒**。
9. **八个主月相**（中文规范名 + 英文）：新月 New Moon、娥眉月 Waxing Crescent、上弦月 First Quarter、盈凸月 Waxing Gibbous、满月 Full Moon、亏凸月 Waning Gibbous、下弦月 Last Quarter、残月 Waning Crescent。（第 2 个名字中文有"蛾眉月/娥眉月"两种写法，页面用哪个**你定死**并保持全文一致。）
10. **上弦月**约正午升起、午夜落下；**下弦月**约午夜升起、正午落下。
11. 真实月面**反照率只有约 0.12**（比沥青还暗）；满月看起来亮是**相效应（opposition surge）**造成的，晴空正午太阳照度约 10 万 lux，满月仅约 0.25 lux。

## 已验证的依赖与数据（策展阶段本机实测，直接用，别自己发明）
- **推荐依赖：`suncalc` v2.1.1**（npm，零依赖、纯本地计算、MIT；作者 Vladimir Agafonkin）。已实测安装可用。**v2 API（务必按此写）**：
  - `getMoonIllumination(date?: Date) → { fraction: 0(新月)~1(满月), phase: 0新月/0.25上弦/0.5满月/0.75下弦, angle: 亮面边缘位角(度), waxing: 盈/亏 }`
  - `getMoonTimes(date, lat, lng, utcOffset?) → { rise?, set?, transit?, lowerTransit?, alwaysUp?, alwaysDown? }`（`utcOffset` 单位分钟、东正；按**民用日**计算，缺省会退回太阳日）
  - `getMoonPosition(date, lat, lng) → { azimuth, altitude, distance(km), parallacticAngle }`
  - `getTimes(date, lat, lng, height?, utcOffset?)`、`getPosition(date, lat, lng)`
- **黄金值（页面算法必须满足）**：在下列 UTC 时刻，`fraction` 必须 ≈ 0（新月）或 ≈ 1（满月），偏差 ≤ 0.002：
  2000-01-06 18:14 新月 → 0.0002；2000-01-21 04:41 满月 → 1.0000；2024-01-11 11:57 新月 → 0.0019；2024-01-25 17:54 满月 → 0.9983；2026-03-03 11:34 满月 → 1.0000；2026-03-19 01:06 新月 → 0.0002；2026-08-28 04:13 满月 → 1.0000；2026-09-11 03:09 新月 → 0.0002。
- **2026 年全年朔/望时刻**（本机分钟级扫描反推，UTC，可用于更细的回归与文案）：望 01-03 10:26；朔 01-18 20:24；望 02-01 22:32；朔 02-17 12:12；望 03-03 11:34；朔 03-19 01:06；望 04-02 01:44；朔 04-17 11:27；望 05-01 17:00；朔 05-16 19:54；望 05-31 08:53；朔 06-15 03:11；望 06-30 00:28；朔 07-14 10:09；望 07-29 15:00；朔 08-12 17:46；望 08-28 04:13；朔 09-11 03:09；望 09-26 16:22；朔 10-10 15:20；望 10-26 03:52；朔 11-09 06:53；望 11-24 15:00；朔 12-09 01:16；望 12-24 01:53。
- **精度已知边界**：上述朔/望时刻与 USNO /《Astronomical Almanac》真实星历可差 **15–60 分钟**（低精度星历的固有限制）；照明比例本身误差 < 0.002。用于教学展示够用。若你要更高精度，请自己说明取舍并给出依据。
- **连续性实测**：相邻两日 `fraction` 单调变化，日变化量最大约 0.11（在上下弦附近），朔/望附近平缓 → 日期滑块插值平滑，不会出现跳变。
